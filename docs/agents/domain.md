# Domain docs

Use a single-context layout: root `GLOSSARY.md` and `docs/adr/`.

Before exploring, read the glossary and ADRs relevant to the work.
If these do not exist, proceed silently. Domain modeling creates
them when terms or decisions are resolved; do not create placeholders.

Use the glossary's vocabulary when naming domain concepts.
Reconsider unfamiliar terms or note genuine gaps for domain modeling.

Explicitly flag proposals that contradict an existing ADR.
